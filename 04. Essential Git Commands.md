# 04. Essential Git Commands

This guide covers the core Git commands used in daily software development for initializing repositories, staging files, creating commits, and managing tracked files.

---

## 1. Initializing a Repository

To create a new local Git repository in your current working directory:

```bash
git init
```

Set the initial default branch explicitly to `main`:
```bash
git init -b main
```

Output:
```text
Initialized empty Git repository in /projects/app/.git/
```

---

## 2. Checking Repository Status

Inspect which files are untracked, modified, or staged:

```bash
git status
```

### Short Status (`-sb`)
For a compact status output displaying current branch information and status codes:

```bash
git status -sb
```

Example output:
```text
## main...origin/main [ahead 1]
 M src/index.js
A  src/components/Nav.js
?? docs/notes.txt
```

Legend:
- `??` : Untracked file
- ` M` : Modified in working tree (not staged)
- `M ` : Modified and staged
- `A ` : Added / staged new file
- `D ` : Deleted file

---

## 3. Staging Changes (`git add`)

Move changes from your working tree into the staging area:

### Stage a specific file:
```bash
git add src/index.js
```

### Stage all modified and new files:
```bash
git add .
```

### Interactive Patch Staging (`git add -p`)
To stage parts of a file rather than all modifications at once:

```bash
git add -p src/index.js
```

Git presents each distinct change "hunk" with options:
- `y` : Stage this hunk
- `n` : Do not stage this hunk
- `s` : Split the hunk into smaller hunks
- `q` : Quit interactive staging

---

## 4. Saving Snapshots (`git commit`)

Record staged changes into the local repository with an informative commit message:

```bash
git commit -m "feat(auth): implement token verification middleware"
```

### Amending the Last Commit
If you forgot to add a small change or want to correct the last commit message before pushing:

```bash
git add forgotten-file.js
git commit --amend --no-edit
```

> [!WARNING]
> Only amend commits that have **not** been pushed to a shared remote repository. Amending generates a new commit hash and rewrites history.

---

## 5. Modern File Restoration (`git restore`)

Git 2.23 introduced `git restore` to handle file restorations without the confusion of overloaded legacy commands (`git checkout --` and `git reset HEAD`).

### Unstage a staged file (keep working tree edits):
```bash
git restore --staged src/index.js
```

### Discard local modifications in working tree:
```bash
git restore src/index.js
```

> [!CAUTION]
> Discarding working tree modifications permanently overwrites your uncommitted edits. Git has no record of unstaged changes; this action cannot be undone.

---

## 6. File Operations: Moving and Removing

### Stop tracking a file without deleting it from disk:
Useful when you accidentally tracked a file that belongs in `.gitignore`:

```bash
git rm --cached .env
```

### Remove a file from disk and stage the removal:
```bash
git rm deprecated-file.js
```

### Move or rename a tracked file:
```bash
git mv old-name.js new-name.js
```
Git automatically records this as a staged rename operation.

---

## Command Reference

| Command | Description |
|---|---|
| `git init -b main` | Initialize a new repository with default branch `main` |
| `git status -sb` | Display concise branch and file status |
| `git add <file>` | Stage file for commit |
| `git add -p` | Interactively stage change hunks |
| `git commit -m "<msg>"` | Record snapshot to repository history |
| `git commit --amend` | Modify the most recent unpushed commit |
| `git restore --staged <file>` | Unstage a file while preserving local changes |
| `git restore <file>` | Discard uncommitted changes in working tree |
| `git rm --cached <file>` | Untrack file from Git without deleting from disk |
| `git mv <old> <new>` | Rename or move a tracked file |
