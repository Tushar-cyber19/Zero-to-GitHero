# 16. GitHub Security & Repository Management

Maintaining a secure, collaborative repository requires automated security scanning, policy controls on main branches, and review assignments.

---

## 1. Repository Rulesets and Branch Protection

GitHub Repository Rulesets provide centralized governance over branches and tags.

### Standard Production Branch Policies (`main`):
In **Settings** -> **Rules** -> **Rulesets**:
- **Restrict deletions:** Blocks accidental deletion of critical branches.
- **Block force pushes:** Prohibits `git push --force` to protect history integrity.
- **Require a pull request before merging:**
  - Mandate at least one approving review.
  - Dismiss stale reviews when new commits are pushed.
  - Require review from Code Owners.
- **Require status checks to pass:** Ensure CI/CD workflows succeed before merges are allowed.
- **Require linear history:** Enforce squash or rebase merges to prevent merge bubbles.

## 2. Review Assignment (`CODEOWNERS`)

Create `.github/CODEOWNERS` to automatically assign reviewer teams based on file paths:

```text
# Repository-wide owner
* @Tushar-cyber19

# Security configurations and workflows
.github/workflows/  @devops-lead
/security/          @security-team

# Markdown documentation
*.md                @docs-team
```

When pull requests touch matching files, GitHub automatically adds the designated owners as requested reviewers.

---

## 3. Automated Dependency Scanning (Dependabot)

Dependabot scans dependencies for reported vulnerabilities (CVEs) and opens automated pull requests with version updates.

Create `.github/dependabot.yml`:

```yaml
version: 2
updates:
  - package-ecosystem: "npm"
    directory: "/"
    schedule:
      interval: "weekly"
    open-pull-requests-limit: 5

  - package-ecosystem: "github-actions"
    directory: "/"
    schedule:
      interval: "monthly"
```

---

## 4. Secret Scanning & Push Protection

Exposing API keys, cloud tokens, or certificates in public repositories presents severe security risks.

In **Settings** -> **Code security and analysis**:
- **Secret Scanning:** Scans repository history for known token signatures.
- **Push Protection:** Inspects commits during `git push`. If a recognized credential pattern is detected, GitHub immediately blocks the push before the secret reaches remote servers.

---

## 5. Static Code Analysis (CodeQL)

CodeQL scans codebases for security vulnerabilities, memory corruption patterns, and injection flaws.

To activate:
1. Navigate to **Settings** -> **Code security and analysis**.
2. Under **Code scanning**, click **Set up** -> **Default**.
3. CodeQL will analyze all subsequent pull requests automatically.
