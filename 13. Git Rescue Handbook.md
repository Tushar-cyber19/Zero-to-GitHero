# 13. Git Rescue Handbook

This handbook details recovery strategies for common Git errors, such as undoing hard resets, salvaging deleted branches, recovering detached heads, and inspecting the local reference log (`git reflog`).

---

## 1. The Git Reference Log (`git reflog`)

Git maintains a local log of every update made to the `HEAD` reference. Whenever you commit, switch branches, rebase, merge, or reset, Git records the previous position.

Because objects in Git are not discarded immediately, reference logs allow you to locate and restore commits that are no longer accessible from any branch tip.

```bash
git reflog
```

Example output:
```text
7b3e1a2 (HEAD -> main) HEAD@{0}: reset: moving to HEAD~2
4c8d9e0 HEAD@{1}: commit: feat: complete payment integration
1a2b3c4 HEAD@{2}: commit: feat: add webhook listener
9e8f7a6 HEAD@{3}: checkout: moving from feature/cart to main
```

- `HEAD@{0}`: The current position of `HEAD`.
- `HEAD@{1}`: The position of `HEAD` one action prior.
- The 7-character identifier on the left is the exact commit hash.

---

## 2. Restoring Work after `git reset --hard`

### The Problem:
You ran `git reset --hard HEAD~2` and recent commits no longer appear in `git log`.

### The Solution:
1. Run `git reflog` to identify the commit hash prior to the reset:
   ```bash
   git reflog
   ```
2. Identify the hash (e.g., `4c8d9e0`).
3. Create a recovery branch pointing to that commit:
   ```bash
   git switch -c recovered-work 4c8d9e0
   ```
All files and commit history are restored onto the new branch.

---

## 3. Restoring an Accidentally Deleted Branch

### The Problem:
A branch was deleted using `git branch -D feature/analytics`.

### The Solution:
1. Run `git reflog` and locate the last commit hash recorded for that branch.
2. Re-create the branch from that commit:
   ```bash
   git switch -c feature/analytics 8f9a0b1
   ```

---

## 4. Recovering from Commits Made Directly on the Wrong Branch

### The Problem:
Commits intended for a new feature were accidentally committed onto `main`.

### The Solution:
```bash
# 1. Create the new branch at current HEAD (preserving your commits)
git branch feature/new-work

# 2. Reset the local main branch backward to clean up
git reset --hard HEAD~2

# 3. Switch to your feature branch
git switch feature/new-work
```

---

## 5. Canceling or Undoing Rebase Operations

- **If rebase is currently in progress:**
  ```bash
  git rebase --abort
  ```
- **If rebase has already completed:**
  1. Inspect `git reflog` for the entry `rebase (start)`.
  2. Reset your branch to the commit immediately before that point:
     ```bash
     git reset --hard HEAD@{3}
     ```

---

## 6. Understanding Data Recovery Boundaries

| Command | Recoverable via Reflog? | Explanation |
|---|---|---|
| `git reset --hard` | Yes | Committed objects remain stored in repository object database. |
| `git branch -D` | Yes | Branch tip commits persist and can be referenced via hash. |
| `git restore <file>` | No | Unstaged changes in working tree are overwritten and were never stored. |
| `git clean -fd` | No | Untracked files were never recorded in Git database. |
