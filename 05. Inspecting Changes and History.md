# 05. Inspecting Changes and History

Investigating commit history and comparing diffs are essential skills for code review, debugging regressions, and auditing codebase evolution.

---

## 1. Comparing Changes (`git diff`)

`git diff` reveals line-by-line modifications before and after staging.

### Compare Working Directory against Staging Area:
Shows what you modified in your files that has not yet been staged with `git add`:

```bash
git diff
```

### Compare Staged Area against HEAD (Last Commit):
Shows what changes are staged and will be included in the next commit:

```bash
git diff --staged
```

### Compare Two Commits or Branches:
```bash
git diff main..feature/auth
```

### Compare Specific Files Across Branches:
```bash
git diff main..feature/auth -- src/config.js
```

### Summary of Changed Files (`--stat`):
Displays a list of modified files with insertion and deletion metrics:

```bash
git diff --stat HEAD~3 HEAD
```

---

## 2. Viewing Commit History (`git log`)

### Standard Log:
```bash
git log
```

### Compact One-Line History:
```bash
git log --oneline
```

### Graphical Multi-Branch Commit Tree:
Visualizes branch divergence, merges, and commit tags in terminal:

```bash
git log --oneline --graph --decorate --all
```

Example output:
```text
* 7f2b1a0 (HEAD -> main, origin/main) feat: add user settings page
*   3e4a1b2 Merge branch 'feature/login' into main
|\  
| * d9e0f12 feat: add password reset form
| * 5c6b7a8 feat: add authentication token handler
|/  
* 1a2b3c4 chore: initial commit
```

### Limiting Commit Logs:
- Show last 5 commits: `git log -n 5 --oneline`
- Commits by author: `git log --author="Jane"`
- Commits since a date: `git log --since="2 weeks ago"`
- Commits touching a specific file: `git log -p -- src/auth.js`

---

## 3. Inspecting Git Objects (`git show`)

Inspect the metadata and full diff of a commit, tag, or object:

```bash
# View last commit
git show HEAD

# View specific commit
git show 7f2b1a0

# View annotated tag details
git show v1.0.0
```

---

## 4. Line-by-Line Attribution (`git blame`)

`git blame` displays the commit hash, author name, and timestamp for the commit that last changed each line of a file. It is invaluable for understanding why a line of code was introduced.

```bash
git blame src/index.js
```

### Limit to Specific Line Ranges (`-L`):
```bash
git blame -L 40,60 src/index.js
```

Example output:
```text
5c6b7a8a (Jane Doe  2025-10-14 11:20:15 +0200 42) const token = req.headers['authorization'];
5c6b7a8a (Jane Doe  2025-10-14 11:20:15 +0200 43) if (!token) return res.status(401).send();
```

---

## 5. Searching Tracked Files (`git grep`)

Quickly search tracked files for strings or regular expressions without needing external tools like `grep` or `findstr`:

```bash
# Case-insensitive search
git grep -i "jwt_secret"

# Show line numbers
git grep -n "handleLogin"

# Count occurrences per file
git grep -c "TODO"
```

---

## Inspection Commands Reference

| Command | Purpose |
|---|---|
| `git diff` | Show unstaged modifications in working tree |
| `git diff --staged` | Show changes staged for the next commit |
| `git diff <branch1>..<branch2>` | Compare differences between two branches |
| `git log --oneline --graph --all` | Formats commit history into a graphical tree |
| `git show <commit>` | Display metadata and patch for a specific commit |
| `git blame -L <start>,<end> <file>` | Identify author and commit for specific lines |
| `git grep -n "<pattern>"` | Search repository files for string patterns |
