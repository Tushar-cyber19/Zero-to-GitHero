# 01. Introduction to Git and GitHub

Welcome to the **Zero-to-GitHero** learning journey. In this section, you will learn what Git and GitHub are, why version control is essential to software development, and how professional teams use them to collaborate reliably.

---

## What is Git?

Git is a free, open-source distributed version control system (VCS) created by Linus Torvalds in 2005.

It enables developers to:
- Track changes in files and directories over time.
- Work on separate features simultaneously without affecting stable code.
- Revert files or entire project states to previous revisions.
- Merge contributions from multiple developers into a single project.

---

## What is GitHub?

GitHub is a cloud-based hosting platform for Git repositories.

It provides:
- Remote storage and backup for your local repositories.
- Team collaboration tools including Pull Requests, Issues, and Code Reviews.
- Automation capabilities through GitHub Actions for testing and deployment.
- Project management tools including Project Boards and Discussions.

In short: Git is the underlying command-line tool installed on your computer; GitHub is the platform used to share, review, and collaborate on those Git repositories.

---

## Git vs GitHub: Key Differences

| Feature | Git | GitHub |
|---|---|---|
| **Category** | Distributed Version Control System | Web-based hosting service and platform |
| **Location** | Runs locally on your machine | Runs in the cloud |
| **Network Requirement** | Works completely offline | Requires internet connection |
| **Core Function** | Tracks commit history, branches, diffs | Facilitates collaboration, PR reviews, CI/CD |
| **Interface** | Command-line interface (CLI) and GUI tools | Web browser interface, mobile app, and GitHub CLI (`gh`) |

---

## Why Version Control Matters

Without version control, managing project history relies on error-prone manual backups (e.g., `project_final_v2_really_final.zip`).

With Git:
- **Complete Audit Trail:** Every commit records who made the change, when it occurred, and why.
- **Safe Experimentation:** Branches allow experimenting freely; failed experiments can be deleted without risking production code.
- **Traceable Rollbacks:** Any change can be inspected, compared, or rolled back cleanly.

---

## Core Terminology

| Term | Definition |
|---|---|
| **Repository (Repo)** | A project directory tracked by Git, containing all project files and history inside a `.git` folder. |
| **Commit** | A permanent snapshot of your staged changes saved to the repository history. |
| **Branch** | A lightweight movable pointer to a commit, representing an independent line of development. |
| **Merge** | The process of combining commit histories from two distinct branches. |
| **Remote** | A version of your repository hosted on a remote server, such as GitHub. |
| **Clone** | A local copy of a remote repository with full history and remote-tracking branches. |

---

## Basic Workflow Overview

A standard day-to-day workflow consists of four simple steps:

1. Clone or initialize a repository:
   ```bash
   git clone https://github.com/username/repo-name.git
   ```
2. Make edits, then stage and commit them:
   ```bash
   git add .
   git commit -m "feat: implement initial project setup"
   ```
3. Push your commits to GitHub:
   ```bash
   git push -u origin main
   ```
4. Pull updates from your team:
   ```bash
   git pull origin main
   ```
