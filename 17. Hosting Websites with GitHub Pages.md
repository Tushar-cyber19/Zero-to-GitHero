# 17. Hosting Websites with GitHub Pages

GitHub Pages is a static site hosting service designed to publish web assets directly from a GitHub repository.

---

## 1. Hosting Architecture & Scope

GitHub Pages serves static web files (HTML, CSS, JavaScript, images, and client-side bundles).

### What GitHub Pages Can Host:
- Static portfolios, documentation, and project demonstrations.
- Single-page applications built with React, Vue, Svelte, or Vite.
- Static exports from frameworks (such as Next.js configured with `output: 'export'`).

### What GitHub Pages Cannot Host:
> [!IMPORTANT]
> GitHub Pages does not include a server-side execution runtime. It cannot run Node.js, Python, PHP, or Ruby application servers, and cannot process server-rendered pages (SSR), Next.js server actions, or direct database connections. Applications requiring backend services must host their APIs on an external service.

## 2. Deployment Methods

### Method A: Deploy from a Branch
Suitable for plain HTML/CSS/JS repositories:
1. Navigate to **Settings** -> **Pages**.
2. Under **Build and deployment** -> **Source**, select **Deploy from a branch**.
3. Choose branch: `main` and directory: `/ (root)` or `/docs`.
4. Click **Save**.

### Method B: Deploy via GitHub Actions
Recommended for applications requiring a build step (Vite, Webpack, static export):

```yaml
# .github/workflows/deploy-pages.yml
name: Deploy to GitHub Pages

on:
  push:
    branches: ["main"]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build-and-deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: "npm"
      - run: npm ci
      - run: npm run build
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: "./dist"
      - id: deployment
        uses: actions/deploy-pages@v4
```

## 3. Subpath Asset Routing in Project Sites

For project repositories, your site URL contains a subpath:
`https://<username>.github.io/<repository-name>/`

Absolute paths (such as `/style.css`) resolve to the domain root rather than the project subdirectory. Always configure bundler base paths:

- **In Vite (`vite.config.js`):**
  ```javascript
  export default defineConfig({
    base: '/<repository-name>/',
  })
  ```
- **In Next.js (`next.config.js`):**
  ```javascript
  module.exports = {
    output: 'export',
    basePath: '/<repository-name>',
    images: { unoptimized: true },
  }
  ```

## 4. Custom Domains and HTTPS

To use a custom domain (such as `www.example.com`):
1. Configure DNS records with your registrar:
   - For an apex domain (`example.com`): Add `A` records pointing to GitHub Pages IP addresses (`185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`).
   - For a subdomain (`www.example.com`): Add a `CNAME` record pointing to `<username>.github.io`.
2. In repository **Settings** -> **Pages** -> **Custom domain**, add your domain and click **Save**.
3. Check **Enforce HTTPS** to mandate encrypted connections via automatic SSL certificates.
